# База данных для приложения знакомств

## Описание
База данных SQL Server 2008 R2 для веб-приложения знакомств с полным функционалом для управления пользователями, профилями, матчами и чатами.

## Требования
- SQL Server 2008 R2 или выше
- SQL Server Management Studio (SSMS) для удобной работы
- Права администратора для создания базы данных

## Структура базы данных

### Основные таблицы

#### 1. Users - Пользователи
- **UserId** - Уникальный идентификатор пользователя
- **Username** - Имя пользователя для входа
- **Email** - Email адрес
- **PasswordHash** - Хеш пароля
- **Name** - Реальное имя
- **Age** - Возраст
- **Gender** - Пол
- **Bio** - О себе
- **Location** - Местоположение
- **Avatar** - URL аватара
- **IsOnline** - Статус онлайн
- **LastSeen** - Последний раз онлайн
- **CreatedAt** - Дата создания
- **UpdatedAt** - Дата обновления
- **IsActive** - Активен ли аккаунт

#### 2. UserPhotos - Фотографии пользователей
- **PhotoId** - Уникальный идентификатор фото
- **UserId** - Ссылка на пользователя
- **PhotoUrl** - URL фотографии
- **IsMain** - Главное фото
- **OrderIndex** - Порядок отображения
- **CreatedAt** - Дата загрузки

#### 3. Interests - Интересы
- **InterestId** - Уникальный идентификатор интереса
- **Name** - Название интереса
- **Category** - Категория

#### 4. UserInterests - Связь пользователей и интересов
- **UserId** - Ссылка на пользователя
- **InterestId** - Ссылка на интерес

#### 5. Likes - Лайки
- **LikeId** - Уникальный идентификатор лайка
- **FromUserId** - Кто лайкнул
- **ToUserId** - Кого лайкнули
- **LikeType** - Тип лайка (like/superlike)
- **CreatedAt** - Дата лайка

#### 6. Matches - Матчи
- **MatchId** - Уникальный идентификатор матча
- **User1Id** - Первый пользователь
- **User2Id** - Второй пользователь
- **MatchedAt** - Дата матча
- **IsActive** - Активен ли матч

#### 7. Chats - Чаты
- **ChatId** - Уникальный идентификатор чата
- **MatchId** - Ссылка на матч
- **CreatedAt** - Дата создания
- **IsActive** - Активен ли чат

#### 8. Messages - Сообщения
- **MessageId** - Уникальный идентификатор сообщения
- **ChatId** - Ссылка на чат
- **FromUserId** - От кого сообщение
- **MessageText** - Текст сообщения
- **MessageType** - Тип сообщения (text/photo/emoji)
- **PhotoUrl** - URL фото (если есть)
- **IsRead** - Прочитано ли
- **CreatedAt** - Дата отправки

#### 9. UserSettings - Настройки пользователей
- **UserId** - Ссылка на пользователя
- **MaxDistance** - Максимальное расстояние для поиска
- **MinAge** - Минимальный возраст для поиска
- **MaxAge** - Максимальный возраст для поиска
- **ShowMen** - Показывать мужчин
- **ShowWomen** - Показывать женщин
- **Notifications** - Уведомления включены
- **Privacy** - Приватность профиля
- **UpdatedAt** - Дата обновления настроек

## Установка и настройка

### 1. Подключение к SQL Server
1. Откройте SQL Server Management Studio
2. Подключитесь к серверу: `DESKTOP-0S7BADL\SQLEXPRESS`
3. Используйте логин: `sa` и пароль: `123`

### 2. Создание базы данных
1. Откройте файл `create_database.sql`
2. Выполните скрипт полностью
3. Убедитесь, что база данных `DatingApp` создана

### 3. Заполнение тестовыми данными
1. Откройте файл `seed_data.sql`
2. Выполните скрипт для заполнения тестовыми данными
3. Проверьте количество записей в каждой таблице

### 4. Проверка установки
Выполните запрос для проверки:
```sql
USE DatingApp;
SELECT 'Users' as TableName, COUNT(*) as RecordCount FROM Users
UNION ALL
SELECT 'UserPhotos', COUNT(*) FROM UserPhotos
UNION ALL
SELECT 'Interests', COUNT(*) FROM Interests
UNION ALL
SELECT 'UserInterests', COUNT(*) FROM UserInterests
UNION ALL
SELECT 'Likes', COUNT(*) FROM Likes
UNION ALL
SELECT 'Matches', COUNT(*) FROM Matches
UNION ALL
SELECT 'Chats', COUNT(*) FROM Chats
UNION ALL
SELECT 'Messages', COUNT(*) FROM Messages
UNION ALL
SELECT 'UserSettings', COUNT(*) FROM UserSettings;
```

## Безопасность

### 1. Пароли
- Все пароли хранятся в виде хешей
- Рекомендуется использовать bcrypt для хеширования

### 2. SQL Injection
- Все запросы используют параметризованные запросы
- Защита от SQL injection атак

### 3. Права доступа
- Используется минимально необходимый набор прав для пользователя `sa`
- В продакшене рекомендуется создать отдельного пользователя с ограниченными правами

## Устранение неполадок

### 1. Проблемы подключения
- Проверьте правильность имени сервера
- Убедитесь, что SQL Server запущен
- Проверьте настройки брандмауэра

### 2. Проблемы с правами
- Убедитесь, что пользователь `sa` имеет необходимые права
- Проверьте настройки аутентификации SQL Server

### 3. Проблемы с версией
- SQL Server 2008 R2 поддерживает все используемые функции
- При использовании более новых версий может потребоваться обновление синтаксиса
